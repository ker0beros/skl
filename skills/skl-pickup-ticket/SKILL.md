## User Input

```text
$ARGUMENTS
```

Parse from the input, in any order:
- an **issue number** (`#42` or `42`) → **single-ticket mode**: work only that issue, then STOP.
- **`--auto`** → zero-prompt / unattended: pass through to `/skl-fix` and `/skl-feature` so they skip
  spec-clarification questions and the approval gate and proceed with the recommended defaults; suppress
  all await-input Telegram pings.
- **`--alive`** → poll **every 30 min indefinitely** — never exit on empty polls (ignore the 3-poll cap).

Empty input (no number) → **loop mode** over `loop-ready` issues, oldest first.

---

## What this command does

`/skl-pickup-ticket` is skl's **autonomous ticket runner** — the consumer of the human-gated
`loop-ready` queue that the other skills refer to. It fetches the **oldest open issue labeled
`loop-ready`**, classifies it as a **bug** or a **feature**, works it end-to-end through the existing
QA-gated build loop (`/skl-fix` for bugs, `/skl-feature` for features, max 10 iterations each), **opens a
PR that closes the issue** (it never merges), then moves to the **next-oldest** ticket. When the queue is
empty it **waits 30 min and re-polls**; after **3 consecutive empty polls** it **exits** and requires a
manual re-run — unless `--alive`, in which case it polls forever.

This skill embodies the repo's **loop-engineering** posture: the `loop-ready` label is the per-ticket
**human gate** (a human curates what the loop may touch — this skill never applies `loop-ready` itself),
**PR-not-merge** is the integration gate (a human reviews & merges), the **10-iteration defer** and the
**3-empty-poll exit** are the stop rules, and **`--auto --alive`** is the explicit opt-in to L3
(unattended, indefinite) autonomy.

**Read `resources/project.config.md` FIRST**, and read **`resources/pickup-loop.md`** for the exact
per-provider poll / label / PR commands and the wait mechanism. Honor the project **constitution** +
`CLAUDE.md`. The QA gate is **identical** to skl-feature's/skl-fix's — it is owned by those skills; this
driver only sequences them and handles the PR + queue.

## Config (read from `resources/project.config.md`; fall back to these defaults if a key is absent)

- **`pickup_label`** — the eligibility gate (default **`loop-ready`**).
- **`pickup_blocked_label`** — applied when a ticket is deferred (default **`loop-blocked`**).
- **`pickup_poll_interval`** — wait between empty polls (default **`30m`** → 1800s).
- **`pickup_empty_limit`** — consecutive empty polls before exit (default **`3`**; ignored under `--alive`).
- **`pr_base_branch`** — PR/MR target (default: the repo's default branch, via
  `git symbolic-ref --short refs/remotes/origin/HEAD` → strip `origin/`).

## Phase 0 — Preconditions (once per invocation, before any ticket)

1. Read `resources/project.config.md` (surface, gate commands, `gate_strictness`, the pickup keys above).
2. **Resolve the provider + auth** (see `resources/pickup-loop.md`): GitHub → `gh auth status` (must have
   `repo` scope + PR create); GitLab → `glab auth status` (needs `api` scope for MR create; self-hosted
   via `GITLAB_HOST`). If issue access later fails on an auth wall, walk the user through
   `.claude/skills/skl-fix/resources/issue-access.md`, then retry.
3. **Resolve `pr_base_branch`** and confirm the working tree is clean (stash/mention if not).
4. **State file.** Read/create `.skl-pickup/state.md` (template: `resources/state-template.md`) — it holds
   the empty-poll counter, the session skip-list, and the per-ticket result log. It makes the loop
   **idempotent + resumable**: a `ScheduleWakeup` re-enters this skill and re-reads this file.

## Single-ticket mode (`#N` given)

An explicit number **is** the human authorization, so it **bypasses the `loop-ready` gate**. Do the
per-ticket sequence below (steps 2→5) for issue `#N`, then **STOP** — no polling, no next ticket.

---

## Loop mode (no number) — repeat until a stop condition fires

### 1. Poll for the next ticket
Fetch the **oldest open issue labeled `pickup_label`**, excluding any id in the state file's skip-list
(exact commands in `resources/pickup-loop.md`). Then:
- **A ticket is found** → set the empty-poll counter to **0** in the state file → go to step **2**.
- **No eligible ticket:**
  - **`--alive`** → `ScheduleWakeup(delaySeconds = pickup_poll_interval, prompt = "/skl-pickup-ticket <same flags>", reason = "poll loop-ready queue")`, fire `bash ~/.claude/notify-telegram.sh "[<project>] /skl-pickup-ticket 💤 no tickets — re-polling in 30m (alive)"`, and **end the turn**.
  - **not `--alive`** → increment the empty-poll counter:
    - counter **< `pickup_empty_limit`** → `ScheduleWakeup(...)` as above (reason `"poll <n>/<limit>"`), Telegram `💤 no tickets — re-polling in 30m (<n>/<limit>)`, **end the turn**.
    - counter **== `pickup_empty_limit`** → **EXIT**: write the final report, fire `bash ~/.claude/notify-telegram.sh "[<project>] /skl-pickup-ticket ⏹ no tickets after <limit> polls — exiting; re-run /skl-pickup-ticket to resume"`, and **STOP**.

### 2. Classify the ticket
Read the issue title + body and decide **bug** vs **feature** from the content (routing is
content-based, not label-based):
- Defect signals (error/stack trace/crash/regression/"doesn't work"/wrong output) → **bug** → `/skl-fix`.
- New-capability signals (add/support/implement/introduce a behavior or screen) → **feature** → `/skl-feature`.
- Genuinely ambiguous: without `--auto`, ask once (`AskUserQuestion`, fire the await ping); with `--auto`,
  pick the better fit (default to `/skl-feature` if it requests new behavior, `/skl-fix` if it describes a defect).

### 3. Work the ticket on its own branch
Create `skl-pickup/<n>-<slug>` off `pr_base_branch` and stay on it. Then, via the **Skill tool**:
- **bug** → `skl-fix <issue-url>` (fetches the issue, diagnoses the **root cause**, fixes **test-first**,
  QA-gates, and verifies the symptom is gone).
- **feature** → `skl-feature <intent from the issue>` (specify + clarify → plan → … → implement → QA-gates).
- Propagate **`--auto`** so the sub-skill runs zero-prompt. The sub-skill's QA loop (cap **10**) decides
  pass/defer. **The driver owns the branch:** ensure the ticket's commits land on `skl-pickup/<n>-<slug>`
  (if the sub-skill worked on its own `skl-fix/*` / branch, `git merge --no-ff` it into the pickup branch
  before the PR). Never push to / merge into main/dev.

### 4. Resolve the ticket
- **QA passed** → `git push -u origin skl-pickup/<n>-<slug>`, then open a PR/MR (commands in
  `resources/pickup-loop.md`) targeting `pr_base_branch`, title `fix(#n): <slug>` / `feat(#n): <slug>`,
  body = a short summary + the QA evidence + **`Closes #<n>`**. **Do NOT merge.** Record the PR URL in the
  state file; fire `bash ~/.claude/notify-telegram.sh "[<project>] /skl-pickup-ticket ✅ #<n> → PR <url>"`.
- **Deferred** (sub-skill hit the 10-iteration cap) → **remove `pickup_label`, add `pickup_blocked_label`**
  on the issue, **comment the findings** on it (so a human can pick up where the loop stalled), record it
  deferred, and add its id to the skip-list; fire `bash ~/.claude/notify-telegram.sh "[<project>] /skl-pickup-ticket ⚠️ #<n> deferred — labeled <blocked>"`.

### 5. Continue
- **Single-ticket mode** → **STOP** (report the one result).
- **Loop mode** → return to step **1** for the next-oldest ticket (the just-shipped/deferred ticket no
  longer carries `loop-ready`, so it won't be re-picked).

---

## Stop conditions (loop mode)

- **3 consecutive empty polls** (default) → exit; manual `/skl-pickup-ticket` re-trigger required.
- **`--alive`** → never exits on empty polls (only a systemic error or the user stops it).
- **Systemic error** (issue-fetch auth after the access walkthrough, `git push` denied, protected base,
  PR-create permission) → surface the exact error, **STOP** the loop (skipping won't fix a systemic
  problem), Telegram the failure. Never merge.
- **Usage cap** mid-run → the `rate_limit` StopFailure hook fires its alert; use **`/skl-resume`** to
  continue this loop after the reset (it re-enters and re-reads `.skl-pickup/state.md`).

---

## Rules & invariants

- **Human-gated intake.** In loop mode the loop only touches issues labeled `pickup_label` (`loop-ready`);
  it **never applies `loop-ready` itself** — a human curates the queue. An explicit `#N` is a human
  authorization and bypasses the gate.
- **One ticket at a time, oldest first.** Fully resolve a ticket (PR opened or deferred) before the next.
- **PR, never merge.** Push the per-ticket branch and open a PR/MR that `Closes #<n>`; a human reviews &
  merges. Never push to or merge into main/dev — only the `skl-pickup/*` branch is pushed.
- **Reuses the QA machinery.** Bug path = `/skl-fix`, feature path = `/skl-feature`; the gate + cap-10 +
  remediation are theirs (do not fork the pass-matrix). `--auto` propagates to them verbatim.
- **Defer, don't loop forever.** A ticket that can't converge is relabeled `pickup_blocked_label` +
  commented + skip-listed, so "oldest-first" never re-picks the same unfixable ticket.
- **In-session waits.** Poll gaps use `ScheduleWakeup` (30 min < its 1 h cap → one wakeup per poll), so the
  loop resumes itself in the same context. Do **not** use a cloud cron — it can't drive the local build loop.
- **Idempotent + resumable.** All progress lives in `.skl-pickup/state.md`; re-entry re-reads it (empty-poll
  counter, skip-list, results) and never double-starts a ticket.
- **`gate_strictness` honored** (low/standard/strict + Info; toggle with `/skl-gate`).
- **Telegram** prefix `[<project>]` (repo basename); ping on each PR / defer, on every empty-poll wait, on
  exit, and on systemic failure; suppress await-input pings under `--auto`; skip silently if
  `~/.claude/notify-telegram.sh` is absent.

## Working files
- `.skl-pickup/state.md` at the repo root (counter + skip-list + per-ticket result log).
- Per-ticket build artifacts stay under the sub-skill's own dirs (`specs/<feature>/.skl-fix|.skl-feature/`).
